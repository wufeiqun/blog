## 背景介绍

公司生产环境部署了一套GitLab，网络团队把本地和生产环境的22端口封禁了， 导致开发者没办法通过SSH协议拉代码。22端口封禁的原因是不希望员工直连生产的服务器，这个是合理的。

## 解决思路

调整GitLab的配置， 让GitLab的ssh协议通过一个自定义的非22端口访问。

1. 配置SSH， 让ssh同时支持22和2222（自定义的）端口。修改配置： `/etc/ssh/sshd_config`

```
Port 22
Port 2222

Match LocalPort 2222
    AllowUsers git
    PasswordAuthentication no
    AuthenticationMethods publickey
```

下面的这段配置是安全配置， 让2222只允许git用户使用密钥方式请求， 防止用户直接使用root请求， 增加了服务器的安全性。

2. GitLab配置调整

```
gitlab_rails['gitlab_shell_ssh_port'] = 2222
```

改完配置后重启`gitlab-ctl reconfigure`，这个只控制GitLab页面上克隆地址的显示， 除此之外没有其它作用了。
